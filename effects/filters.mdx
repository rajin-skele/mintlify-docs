## Overview

CSS filter effects like blur, brightness, contrast, grayscale, and drop-shadow are useful for media treatments and layered UI, but they are not currently mapped by the Skelementor importer in the same way as bundled utility classes or supported custom `box-shadow` values.

Use this page as guidance for when filter effects belong in your workflow and how to handle them today.

## Current State

| Capability | Status | Notes |
| ---------- | ------ | ----- |
| Bundled Skelementor filter utilities | Not shipped | No `filter-*` utility family is included in `skelementor-utilities.css` |
| Importer support for CSS `filter` | Not currently mapped | Current importer code does not expose `filter` handling like it does for `box-shadow` |
| Elementor-native visual effects | Available separately | Use native Elementor controls where appropriate |

## Recommended Approach Today

- Use bundled Skelementor utilities for layout, spacing, color, opacity, and sizing
- Use Elementor’s native effect controls when they already cover the filter you need
- Use custom frontend CSS outside the Skelementor import workflow when a true CSS `filter` rule is required

## Common Filter Use Cases

### Image Dimming and Blur

```css
.hero-image-soft {
  filter: brightness(0.8) blur(2px);
}
```

### Grayscale Preview

```css
.card-image-muted {
  filter: grayscale(1);
}
```

### High-Contrast Badge

```css
.badge-boosted {
  filter: contrast(1.15) saturate(1.1);
}
```

## When to Avoid Filters

- When opacity alone already achieves the effect
- When Elementor offers a native control with better editor visibility
- When performance matters on heavy image grids or animated surfaces
- When text readability could be harmed by blur or contrast extremes
