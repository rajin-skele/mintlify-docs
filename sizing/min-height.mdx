## Overview

Skelementor ships two bundled minimum-height helpers:

- `.min-h-screen` for a full viewport minimum
- `.min-h-full` for matching the parent height as a minimum

Use min-height when content should be allowed to grow beyond a baseline height instead of being clipped to a fixed `height`.

Additional **`.min-h-*`** classes mirror the fractional, pixel, and container height tokens on the [Height](/sizing/height) page the same way **`.min-w-3xs` … `.min-w-7xl`** mirror container widths.

## Min Height Utilities

| Class | Value | CSS | Usage |
| ----- | ----- | --- | ----- |
| `.min-h-screen` | 100vh | `min-height: 100vh;` | At least the full viewport |
| `.min-h-full` | 100% | `min-height: 100%;` | At least the parent height |

## Usage

### Minimum Screen Height

```html
<main class="min-h-screen p-6">
  <h1 class="text-3xl font-bold mb-6">
    Page Title
  </h1>
  <p class="text-gray">
    Content that may be longer than the viewport.
  </p>
</main>
```

### Parent-Based Minimum Height

```html
<section class="bg-gray-light rounded-lg p-4" style="height: 24rem;">
  <div class="min-h-full bg-white rounded p-6">
    This panel stays at least as tall as its parent container.
  </div>
</section>
```

## Best Practices

- Use `.min-h-screen` for page shells, hero sections, and empty-state layouts.
- Use `.min-h-full` only when a parent already establishes height.
- Prefer min-height over fixed height when content length may change.
- Combine with `overflow-auto` when a minimum-height region may still need scroll control.
